## 2026-11-03 (4) · 상태별 필터와 주소 쿼리 (데스크톱 A, 자동 작업)

### 한 일
- 진행 순서: 문서(DESIGN 2.1 · 3.2 · 5장, 0010) · 목업(Library · LibraryMobile 칩) 확인 → `useEntryList` 필터 · 번호표 → 화면 칩 · 빈 결과 → Vitest → 브라우저(일부) → 문서
- `useEntryList`: `status` · `setStatus` · `libraryTotal` · `isFilterEmpty`. 화면은 `?status=`를 지켜보다 `setStatus`를 부른다
- `parseStatusFilter`(주소 값 → 상태)
- 검증
  - `npm test` **119 passed** (9건 추가), `lint` · `format:check` · `vue-tsc` 통과
  - 브라우저: `/library?status=CLEARED`로 바로 들어가 `클리어` 칩이 눌린 채 2개만 보임, 요약 줄은 `총 3개 · 미시작 1개`(전체 기준)
  - **확인 못 한 것**: 칩을 눌러 바꾸기, "해당 상태의 게임이 없습니다", `?status=abc` 고쳐 쓰기, 모바일 가로 스크롤 칩, 라이트 테마. 확인 도중 사용자가 브라우저 창을 쓰기 시작해 조작을 멈췄다. 이 셋은 Vitest로만 묶여 있다

### [설계]
- **주소가 원본, 칩은 주소만 바꾼다**: 칩이 목록을 직접 부르고 주소도 바꾸면 한 번에 두 번 불린다. 주소를 지켜보는 쪽 하나만 부른다
- **`router.replace`**: 칩마다 방문 기록이 쌓이면 뒤로가기로 라이브러리를 빠져나가지 못한다. 상세에서 돌아올 때는 주소에 필터가 남아 있어 같은 목록이 보인다
- **요약 줄은 라이브러리 전체 기준**: 필터를 걸 때마다 `총 N개`가 바뀌면 "라이브러리가 줄었나?"로 읽힌다. 전체 · 미시작 개수 중 목록 응답으로 알 수 있는 것은 다시 묻지 않는다(요청 2번 유지)
- **필터를 바꾸면 목록을 바로 비운다**: 새 칩이 눌린 채 앞 필터의 게임이 보이면 잘못 거른 것처럼 읽힌다. 뼈대가 잠깐 보인다
- **빈 상태 둘을 가른다**: 새 계정이 `?status=CLEARED` 주소로 들어오면 "해당 상태의 게임이 없습니다"가 아니라 등록 권유가 맞다(라이브러리 전체 개수로 가른다)
- 정렬은 `PLAN` M3 항목이 아니라 넣지 않았다. `withoutStatus()`는 나중에 붙을 `?sort=`를 지우지 않게 해 뒀다

### 막힌 것
- 증상: `parseStatusFilter('toString')`이 `undefined`가 아니라 `'toString'` (테스트에서 발견)
  - 원인: `raw in STATUS_LABEL`은 객체가 물려받은 기본 속성(`toString` 등)도 있다고 답한다. 주소에 `?status=toString`을 치면 서버에 그대로 가서 422
  - 해결: `Object.hasOwn`
  - 배운 것: 주소 값처럼 누구나 넣을 수 있는 문자열을 객체 키로 확인할 때는 `in`을 쓰지 않는다
- 증상: 사전 검증에서 따라가 보니 추가 로딩 중에 필터를 바꾸면 앞 필터의 20 ~ 40번째가 새 목록에 붙는다 (사전 검증에서 발견)
  - 해결: `loadMore`도 번호표를 본다. 테스트 "추가로 불러오는 중에 필터를 바꾸면…"

## 2026-11-03 (3) · 평점 보존 규칙 ─ 수정 요청 본문 (데스크톱 A, 자동 작업)

### 한 일
- 판단: 평점 보존은 서버((1)의 pytest) · 상세 화면((1) · (2), 상태만 보냄) · 등록 폼(상태를 바꿔도 입력값은 화면에 남음)에서 이미 지켜졌다. 남은 곳은 아직 없는 수정 폼이라, 수정 화면이 쓸 본문 규칙을 먼저 만들어 테스트로 묶었다
- `entry-form.ts`: `entryToEditForm`(저장값 → 입력칸 글자), `buildUpdateBody`(입력칸 → PATCH 본문)
- 검증: `npm test` **110 passed** (9건 추가), `lint` · `format:check` · `vue-tsc` 통과. 부르는 화면이 아직 없어 브라우저 확인은 없다

### [설계]
- **숨긴 평점은 안 보낸다(null 아님)**: `buildCreateBody`는 숨긴 평점을 null로 보낸다. 등록에서는 맞지만 수정에서는 지우기가 된다. 그래서 수정용을 따로 만들었다
- **바뀐 칸만 보낸다**: 두 기기 동시 편집을 따라가 보니, 폼을 열어 둔 사이 상세 화면에서 바꾼 평점을 수정 폼이 옛 값으로 덮어쓴다. 손대지 않은 칸은 보내지 않으면 칸이 다를 때는 둘 다 남는다. 같은 칸을 둘이 고치면 나중 저장이 이긴다(감수)
- **비교는 처음 채운 글자로** (사전 검증에서 발견): 시간 칸은 분을 정확히 못 담는다. 100분 → `1.67`시간 → 다시 읽으면 100분이 아니다. 저장값과 비교하면 안 고친 플레이타임이 저장 때마다 바뀐다
- 장르는 이 규칙에 넣지 않았다. 게임에 장르가 있으면 무시되는 규칙(`DATA_MODEL` 2.5절)이라 화면 처리부터 정해야 한다 ─ 수정 화면 작업

## 2026-11-03 (2) · 상세 화면에서 평점 · 한줄평 바로 입력 (데스크톱 A, 자동 작업)

### 한 일
- 판단: 등록 폼(S-03)에는 평점 칸이 이미 있었다(M2.5). 남은 것은 PLAN 완료 기준 "`PLAYING` → `CLEARED`로 바꾸면 평점 입력란이 나타남" ─ 상태를 바꾸는 곳이 상세 화면이라 거기에 입력을 붙였다
- 진행 순서: 등록 폼 · 폼 규칙 확인 → `useEntryDetail`을 `save(changes)`로 넓힘 → 평가 칸 → Vitest → 브라우저 → 문서
- 평가 칸: 클리어 · 포기면 값이 없어도 보인다. 별은 누르면 저장, 한줄평은 입력칸을 열어 저장 · 취소
- (1)에서 만든 `showsRating`이 `entry-form.ts`의 `canRate`와 같은 함수였다 ─ 지우고 `canRate`로 합침
- 검증
  - `npm test` **101 passed**, `lint` · `format:check` · `vue-tsc` 통과. 서버는 안 고침 (pytest는 (1)의 64건 그대로)
  - 브라우저: 기록 37(플레이중, 평가 칸 없음) → 클리어로 바꾸자 별 5개 · "별을 눌러 평점을 남겨요" · `한줄평 남기기`가 나타남
    - 별 3개 누름 → 한줄평 `  끝까지 해 봄  ` 입력 · 저장 → `PATCH /api/entries/37` 200 세 번(상태 · 평점 · 한줄평). 마지막 응답 `rating: 3`, `review: "끝까지 해 봄"` (앞뒤 공백 지워짐)
    - 입력칸을 열면 바로 글자를 칠 수 있다(자동 포커스). 모바일 375에서 별 · 한줄평 · `고치기` 배치 확인
  - **확인 못 한 것**: 저장 실패 시 문구 위치 · 입력칸 유지는 Vitest로만 봤다. 화면 읽기 프로그램으로 별 버튼을 읽어 보지는 않았다

### [설계]
- **별은 바로 저장, 한줄평은 저장 버튼**: 별은 한 번 누르면 끝나는 값이라 상태 select처럼 바로 저장한다. 글은 쓰는 도중에 저장되면 안 되니 입력칸 + 저장 · 취소. 흐려질 때(blur) 저장은 "언제 저장됐지?"가 흐려져서 안 했다
- **세 칸이 저장 잠금 하나를 같이 쓴다**: 상태와 평점을 거의 동시에 바꾸면 두 PATCH가 거꾸로 도착할 수 있다. 칸마다 따로 잠그지 않고 하나로 막았다. 실패 문구만 `failedField`로 그 칸 옆에 둔다
- **비운 한줄평은 null**: 빈 문자열로 저장하면 화면에 `""`만 남는다
- 별 한 칸을 44px로 둬서 목업보다 별 사이가 넓다. 손가락으로 누를 수 있는 크기가 우선이다

    - 상태를 플레이중으로 → 평가 카드가 사라짐, 클리어로 되돌림 → 별 4개 · 한줄평 다시 보임

    - 플레이타임 0 게임: 시간당 비용 `—`. `/library/99999999999` · `/library/1`(내 기록 아님): "게임을 찾을 수 없어요"
  - **확인 못 한 것**: 상태 저장 실패 화면(되돌림 · 문구)은 Vitest로만 봤다. 커버 주소가 깨진 게임의 배경, 아주 긴 제목의 줄바꿈은 화면에서 안 봤다
  - 확인용 계정 · 기록은 개발 DB에 남아 있다 (계정 값은 세션 임시 폴더에만 있음)

### [설계]
- **시간당 비용을 M3에서 응답에 넣음**: `DESIGN` 3.4절이 "서버 계산값"이라 S-04가 기다릴 수 없었다. 건별 값만 계산 필드로 넣고(저장 안 함 ─ 플레이타임을 고치면 바로 다시 계산), 통계 집계는 M4에 남겼다
  - 반올림은 정수로만 계산하는 0.5 올림. `round()`는 0.5를 짝수로 보내서 1원 · 2시간이 0원이 된다(테스트 `(1, 120, 1)`)
  - 구매가를 안 적어도 `—`. `REQUIREMENTS` 5.1절은 플레이타임 0만 적었지만 나눌 값이 없기는 같다
- **상태는 기본 select**: 목업대로. 모바일에서 OS 선택창이 뜨고 키보드 · 화면 읽기가 그대로 된다
- **고르자마자 반영 + 저장 중 잠금**: 점 색 · 평가 카드가 바로 바뀌어야 "바뀌었나?"를 안 묻는다. 대신 두 요청이 거꾸로 도착하지 않게 저장 중에는 잠근다. 실패하면 되돌린다
- **상세 → 상세 이동은 번호표**: 화면이 다시 만들어지지 않고 id만 바뀌어서, 늦게 온 앞 게임 답이 덮어쓸 수 있다. `useSteamSearch`와 같은 방법
- **평가 카드는 값이 있을 때만**: CLEARED인데 평점이 없으면 빈 카드가 된다. 입력은 다음 작업(평점 입력)에서 수정 화면에 붙는다
- **수정 버튼 · ⋮는 아직 안 그림**: 누를 곳 없는 버튼은 고장으로 보인다. 수정 · 삭제 작업에서 같이 붙인다
- 배경 커버는 48rem부터 흐리게(`blur-md`). Steam 커버가 460px 폭이라 넓은 화면에 늘리면 거칠다. 또렷한 커버는 카드가 맡는다

### 막힌 것
- 증상: 사전 검증에서 "주소창에 큰 숫자"를 따라가 보고 테스트를 썼더니 `GET /api/entries/99999999999`가 **500** (사전 검증에서 발견)
  - 원인: id가 Python int라 크기 제한이 없고, asyncpg가 int4 범위를 넘는 값을 쿼리에 넣다가 `DataError`
  - 해결: `_get_my_entry_or_404`에서 `1 <= id <= INT_MAX`가 아니면 DB에 묻지 않고 같은 404. 422로 하면 '없는 id'와 응답이 갈린다
  - 배운 것: 등록 입력은 `INT_MAX`로 막아 뒀는데(M1) 주소 경로의 id는 빠져 있었다. 경로 값도 입력이다
- 증상: 확인용 계정 가입이 422
  - 원인: `.test` 도메인은 email-validator가 받지 않는다(예약 도메인)
  - 해결: `example.com`으로 가입
