# 0019 · Steam 게임의 구매일 · 구매가는 세 겹으로 채우고, 모르는 값은 추정하지 않는다

- **상태**: 채택
- **날짜**: 2026-11-06

## 맥락

이 앱의 숫자(방치일수 · 시간당 비용)는 구매일 · 구매가가 있어야 계산된다. Steam Web API(`GetOwnedGames`)는 둘 다 주지 않는다. M6 동기화로 게임이 수백 개 들어오면 그 게임들은 방치일수 · 시간당 비용이 비어, 앱의 정체성이 반쯤 빠진다(사용자 지적).

| 출처 | 구매일 | 구매가 |
|---|---|---|
| Steam Web API | 없음 | 없음 |
| Steam 구매 기록 페이지(로그인한 본인만) | 있음 | 실제 낸 돈 |
| Steam 라이선스 목록 페이지(로그인한 본인만) | 받은 날 | 없음 |
| 동기화가 처음 본 날 | 하루 오차 | 없음 |
| 스토어 현재 정가 | 없음 | 정가(낸 돈 아님) |

## 결정

1. **첫 동기화 뒤 새로 생긴 게임**은 동기화가 처음 본 날을 구매일로 넣고 "동기화로 추정"으로 표시한다. 자동 동기화(M7)가 매일 돌면 오차는 하루 이내다. 첫 동기화에서 들어온 기존 라이브러리는 처음 본 날이 "오늘"이라 넣지 않는다
2. **기존 라이브러리**는 사용자가 Steam 구매 기록 · 라이선스 목록 페이지를 복사해 붙여넣으면 날짜 · 금액을 읽어 맞춘다. 맞춘 결과를 먼저 보여 주고 확인을 받아 저장한다. 원문은 저장하지 않는다. **M6.5**에서 한다 — 형식을 사용자의 실제 페이지로 확인한 뒤
3. **남은 빈칸**은 빈 게임만 모은 "구매 정보 채우기" 표에서 한 줄씩 넣는다. "무료 · 번들이라 모름"도 고를 수 있다
4. 구매일 · 구매가마다 **어디서 왔는지**(직접 입력 · 구매 기록 · 동기화 추정)를 저장한다. 사용자가 고친 값이 늘 이긴다. 가져오기 · 동기화는 사용자가 넣은 값을 덮어쓰지 않는다
5. **모르는 값은 추정하지 않는다**: 스토어 정가로 채우지 않는다. 빈칸이면 방치일수 자리에 "구매일 모름", 통계에는 "구매가가 적힌 게임 N / M개 기준"을 보인다

Steam 비밀번호 · 로그인 쿠키를 받아 대신 긁어 오지 않는다. 남의 계정 열쇠를 맡는 일이고 Steam 약관에도 걸린다.

## 검토한 대안

- **스토어 현재 정가로 추정 채우기** — 숫자가 빨리 채워지지만 세일가로 산 게임의 시간당 비용이 부풀려진다. 빈칸 + 범위 표시가 더 정직하다 (사용자 선택)
- **가져오기를 M6에 함께** — 처음부터 숫자가 다 차지만 M6이 커진다. 화면 형식 확인이 먼저 필요해 뒤로 뺐다 (사용자 선택)
- **첫 동기화 날을 기존 게임의 구매일로** — 방치일수가 전부 0일이 되어 거짓 숫자가 된다
- **Steam 로그인 쿠키로 구매 기록을 직접 가져오기** — 위 이유로 하지 않는다

## 감수할 것

- 가져오기는 Steam 화면 글자를 읽어서 Steam이 화면을 바꾸면 깨진다. 깨지면 빈칸 채우기 표가 남는다
- 외부에서 산 키 · 번들의 금액은 구매 기록에 없거나 묶여 있어 사용자가 정해야 한다
- 저장 칸이 늘어난다(값마다 출처)
