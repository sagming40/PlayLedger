# 0011 · 직접 등록한 게임은 사용자별로 나누고 Steam 게임만 공유한다

- **상태**: 채택
- **날짜**: 2026-11-04

## 맥락

`games`는 처음에 모두가 공유하는 마스터 데이터로 설계했다. 혼자 쓸 때는 문제가 없었지만 공개 가입을 열면 달라진다.

- 먼저 등록한 사람이 적은 제목 표기가 같은 제목을 적은 다른 사람에게 그대로 보인다. 욕설이나 개인 메모를 제목에 적어도 마찬가지다
- 먼저 붙인 장르가 고정되어 다른 사람의 장르별 통계를 바꾼다. 나중 사람은 고칠 수 없다
- 기록을 지워도 제목과 장르가 DB에 남는다. 계정을 지울 때 "내가 적은 것"을 가려낼 방법이 없다

Steam 게임은 번호와 이름을 서버가 Steam에서 받아 오므로 이런 문제가 없다.

## 결정

`games.owner_user_id`를 둔다. 직접 등록한 게임은 만든 사람이 주인이고, Steam 게임은 주인이 없다. CHECK로 강제한다.

- 중복 판별 · UNIQUE는 한 사람 안에서만 본다
- 장르는 주인이 언제든 바꾼다. Steam 게임은 "0개일 때만 채운다"를 유지한다 (`DATA_MODEL` 2.5절)
- 기록을 지우면 내 게임 행도 지운다
- 기존 데이터는 마이그레이션이 나눈다. 첫 기록의 주인이 원래 행을 갖고, 나머지는 제목 · 장르를 복사한 자기 행을 받는다. 기록 없는 수동 게임은 지운다
- 한 사람의 기록은 5,000개까지로 둔다. 직접 등록할 때마다 게임 행도 늘어나는데, 요청 제한만으로는 전체 크기를 막지 못한다

## 검토한 대안

- **공유를 유지하고 신고 · 관리자 기능(F-23)으로 푼다** — 배포 전에 관리자 화면을 만들어야 하고, 이미 노출된 뒤에야 고칠 수 있다
- **`entries`에 제목을 옮겨 게임 행 없이 기록한다** — 수동 / Steam에 따라 조회 · 통계가 둘로 갈라진다. 지금 구조는 행의 범위만 달라지고 조회는 그대로다
- **공유 행을 두되 표기와 장르만 사용자별로 덮어쓴다** — 표가 하나 더 늘고 통계가 그 표까지 봐야 한다. 나눠서 얻는 이점이 없다

## 감수할 것

- 같은 게임을 여러 사람이 직접 등록하면 행이 그만큼 생긴다. 사람별 상한으로 크기를 제한한다
- 이후 "다른 사람들이 많이 가진 게임" 같은 집계는 직접 등록 게임을 하나로 묶을 수 없다. Steam 게임으로만 가능하다
- 되돌리는(downgrade) 마이그레이션은 같은 제목을 합치며 먼저 만든 행의 표기 · 장르만 남긴다
- Steam이 실패한 첫 등록에서 고른 장르는 Steam 게임에 그대로 남아 다른 사람에게도 보인다. 고정 8개 안의 값이라 위험은 작고, 고치는 것은 F-23에서 다룬다
