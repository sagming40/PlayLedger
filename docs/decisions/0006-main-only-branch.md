# 0006 · 브랜치를 파지 않고 `main`에서만 작업

- **상태**: 채택
- **날짜**: 2026-10-24

## 맥락

2026-09-18부터 마일스톤 단위 브랜치 + PR로 작업했다. 실무 흐름을 익히는 것이 목표였고, M0 · M1은 PR #1 · #2로, M2 앞부분은 `m2-frontend` PR #3으로 병합됐다.
출근 후에는 짧은 세션이 띄엄띄엄 이어진다. 한 달 공백 뒤 재개하니 "다른 기기에 브랜치가 없다"부터 확인해야 했다.

## 결정

브랜치를 따로 파지 않고 `main`에서만 작업한다. CI가 `main` push마다 돌고 검증 전 커밋을 하지 않는 규칙이 브랜치가 하던 보호 역할을 대신한다.

## 검토한 대안

- **마일스톤 브랜치 + PR 유지** — 병합 시점이 마일스톤 완료에 묶여 늦어지고, 기기마다 어느 브랜치를 받아야 하는지 찾아야 한다.

## 감수할 것

- 깨진 커밋이 곧바로 `main`에 들어갈 수 있다. 검증이 끝나지 않은 작업은 커밋하지 않고, CI를 임시 브랜치로 시험할 때만 예외로 브랜치를 쓴다.
