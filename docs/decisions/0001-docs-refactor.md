# 0001 · docs/를 전역 문서 체계로 재정비

- **상태**: 채택
- **날짜**: 2026-11-02

## 맥락

전역 설정에 "문서 체계" 절이 생겼다(기준 모델은 cbt-journal `docs/`). 이 저장소의 문서는 번호 붙은 이름, 문서마다 다른 머리말 · 버전 줄, 긴 변경 이력 표, 코드와 겹치는 컬럼 표, 1,971줄짜리 DEVLOG였다.
이 저장소는 손을 놓은 레포가 아니라 진행 중이고 코드 주석이 절 번호를 100곳 넘게 부른다. 그래서 전역의 "옛 docs를 통째로 archive" 절차 대신 제자리에서 고쳤다.

## 결정

- 파일을 역할 이름으로 바꾼다: `REQUIREMENTS` · `ARCHITECTURE` · `DATA_MODEL` · `DESIGN` · `PLAN`. **절 번호는 가능한 한 유지**해 코드 주석은 문서 이름만 바꾼다.
- `06_api_spec`은 `ARCHITECTURE` 3장으로 합친다. 2026-09-28에 둘을 나눈 이유는 "같은 사실이 두 문서에 생기면 한쪽만 고쳐져 어긋난다"였는데, 한 문서가 되면 그 문제가 사라지고 전역 기준("계약은 ARCHITECTURE")과도 맞는다. 비는 3장(기술 선택 근거)은 0002로 옮겼다.
- 구현된 테이블의 컬럼 표 · 시드 목록 · 구현된 쿼리는 뺀다. 원본은 모델과 마이그레이션이다. 구현 전 테이블과 쿼리만 문서가 원본이다.
- 변경 이력 표, 끝난 M0 · M1의 체크리스트와 DEVLOG 블록은 지우지 않고 `archive/`로 그대로 옮긴다.
- 소급 결정 기록은 지금도 구조를 지배하는 5건(0002 ~ 0006)만 만든다. 나머지 판단은 archive DEVLOG에 있다.
- **"설계 문서를 코드보다 먼저"** 규칙은 "아직 코드가 없는 설계는 문서가 먼저, 코드가 원본인 것은 코드가 먼저"로 좁힌다.

**전역 문서 체계와 다르게 두는 것 하나** — `mockups/`의 `화면.dc.html` 이름을 유지한다 (`화면.기기.html`로 바꾸지 않는다).
디자인 캔버스 원본의 사본이고 `{{ }}` 틀이 그대로 있는 파일이다. 복사본으로 시험해 보니 이름을 바꾸려면 링크 · import 33곳과 `support.js`, `canvas.json`, `.vscode/settings.json`을 같이 고쳐야 했다(고치면 정상 동작). 얻는 것은 이름 모양뿐이고, `canvas.json`이 파일 이름을 키로 쓰므로 캔버스에서 다시 옮겨 올 때 어긋날 수 있다.

## 검토한 대안

- **옛 `docs/`를 통째로 archive하고 새로 쓰기** — 손 놓은 레포용 절차다. 지금 문서가 코드와 대체로 맞고 주석 참조가 많아 잃는 것이 크다.
- **API 명세를 `API.md`로 유지** — 기본 세트에 없는 문서가 남고, 인증 흐름과 계약이 두 문서로 갈린다.
- **결정 기록 약 100건을 전부 `decisions/`로** — 같은 내용이 두 곳에 생기고 대부분 그 시점의 작은 판단이다.
- **코드 주석은 옛 이름 유지** — 수정은 없지만 없는 문서를 가리키게 된다.

## 감수할 것

- archive의 옛 기록은 옛 이름을 그대로 쓴다. `archive/README.md` 대응표로 찾아간다.
- 코드 주석만 고치는 커밋 하나가 생긴다 (동작 변경 없음).
- 캔버스에서 `.dc.html` 이름이 꼭 필요한지는 개인 계정 소유라 회사 계정에서 확인하지 못했다.
