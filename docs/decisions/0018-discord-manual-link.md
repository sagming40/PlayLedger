# 0018 · Discord 계정은 로그인한 상태에서 직접 연결할 때만 잇는다

- **상태**: 채택
- **날짜**: 2026-11-06

## 맥락

`REQUIREMENTS` R-07(같은 사람이 이메일 · Discord로 계정 2개)을 Discord 로그인(M8, 옛 M11) 시작 때 정하기로 했다. 사전 검증에서 다음이 나왔다.

- PlayLedger는 가입할 때 이메일 인증을 하지 않는다(F-27 미구현). 남이 내 이메일로 먼저 가입해 둘 수 있다
- Discord로만 가입한 계정은 비밀번호가 없어 지금의 계정 삭제(비밀번호 확인)를 할 수 없다
- 그런 계정에서 Discord를 해제하면 로그인할 방법이 없어진다

## 결정

- **수동 연결만**: 로그인한 상태에서 설정의 `Discord 연결`로만 잇는다. Discord로 처음 로그인하면 항상 새 계정이 생긴다. 이메일이 같아도 자동으로 잇지 않는다
- **Discord 이메일은 받지 않는다**: 권한은 `identify`만. Discord 전용 계정은 `users.email`이 NULL이다. 저장하는 개인정보가 줄고, 기존 계정 이메일과 부딪히지 않는다
- 새 계정이 생길 때 "이미 이메일 계정이 있다면 그 계정으로 로그인한 뒤 설정에서 연결하세요"를 보이고, 방금 생긴 빈 계정은 그 자리에서 지울 수 있게 한다. 그 이메일의 계정이 있는지는 알려 주지 않는다
- 비밀번호 없는 계정의 삭제는 비밀번호 대신 `계정 삭제`를 직접 입력해 확인한다. 로그인한 사람은 이미 기록을 하나씩 다 지울 수 있어 더 약한 확인이 아니다
- 비밀번호 없는 계정의 마지막 로그인 수단(Discord)은 해제할 수 없다(409). 비밀번호를 더하는 기능은 F-36
- 외부 인증의 `state`는 서명한 쿠키(`SameSite=Lax`, `HttpOnly`, 짧게, 한 번만)에 두고 Steam OpenID(M6)와 같은 모듈을 쓴다. 지금 refresh 쿠키는 `Strict`라 외부 사이트에서 돌아오는 이동에 실리지 않는다

## 검토한 대안

- **이메일 자동 연결** — 편하고 계정이 갈라지지 않는다. 하지만 이메일 인증이 없으면 남이 먼저 만든 계정에 내 Discord가 붙어, 그 사람이 내 기록을 본다(계정 선점). 안전하려면 F-27(메일 발송 · 인증 링크 · 발신 도메인)을 먼저 해야 하고 Discord 이메일을 저장해야 한다. F-27을 만들면 다시 검토한다
- **Discord 이메일을 받아 계정에 채우기** — 기존 계정 이메일과 UNIQUE가 부딪히고 저장 정보가 는다

## 감수할 것

- 연결하지 않고 Discord로 들어오면 빈 계정이 따로 생겨 기록이 갈라질 수 있다 (R-07을 안내와 그 자리 삭제로 줄인다)
- Discord 계정을 잃으면 그 Discord 전용 계정에도 들어갈 수 없다 (F-36 전까지)
