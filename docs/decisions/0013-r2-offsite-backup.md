# 0013 · 서버 밖 백업은 Cloudflare R2에 둔다

- **상태**: 채택
- **날짜**: 2026-11-06

## 맥락

운영 백업(`play-backup`)은 매일 age로 잠가 서버 디스크에만 남았다. 서버가 통째로 사라지거나 12월 이사 중에 실수하면 백업도 같이 사라진다. 서버 밖 사본은 사용자가 PC로 `scp`할 때만 생겼다. 백업 하나는 24KB쯤이다.

## 결정

`play-backup`이 매일 백업을 만든 뒤 Cloudflare R2 버킷에 잠긴 파일 그대로 올린다(`rclone`). R2 사본도 서버와 같이 14일이 지나면 지운다. 개인정보 안내의 "14일"과 맞춘다. 올리기만 실패하면 종료 코드 3을 낸다. 이때 서버 사본은 이미 있으므로 배포는 계속한다.

## 검토한 대안

- **12월 이사 때 AWS S3** — 이사 전 한 달 동안 서버 밖 사본이 없다. 서버와 같은 업체에 두면 계정 하나가 막혔을 때 둘 다 못 쓴다
- **회사 PC가 매일 받아 오기** — PC가 켜져 있을 때만 된다. 비밀번호 없는 전용 SSH 키를 서버에 두고 받기만 하도록 묶어야 해서 오히려 복잡하다
- **Vultr Object Storage** — 월 요금이 있고 서버와 같은 업체다

## 감수할 것

- 도메인과 같은 Cloudflare 계정에 기대는 것이 하나 늘었다. 계정 2단계 인증이 지켜 준다
- 토큰은 버킷 하나의 읽기 · 쓰기만 갖는다. 그래도 서버가 털리면 R2 사본을 지울 수 있다. 내용은 잠겨 있어 읽을 수는 없다
- 백업이 실패해도 알려 주는 곳이 없다. `systemctl --failed`로 직접 본다 (`SERVER` 2절)
