# 0015 · Steam 계정 연결은 ID 입력이 아니라 Steam OpenID로 주인을 확인한다

- **상태**: 채택
- **날짜**: 2026-11-06

## 맥락

처음 설계는 설정 화면에 SteamID64(17자리)를 적게 했다. M8 사전 검증에서 두 문제가 나왔다.

- **선점**: `users.steam_id`는 UNIQUE다(한 Steam 계정의 라이브러리가 두 계정에 복제되지 않게). 그런데 적은 ID가 그 사람 것인지 확인하지 않으면, 다른 사람이 남의 공개 Steam ID를 먼저 적어 진짜 주인이 연결하지 못하게 할 수 있다
- **입력**: 사람들은 SteamID64를 모른다. 프로필 주소나 사용자 이름을 적게 된다

## 결정

설정의 `Steam 계정 연결`을 누르면 Steam 사이트(`steamcommunity.com/openid`)로 가서 로그인하고 돌아온다. 서버는 돌아온 응답을 Steam에 다시 물어(`check_authentication`) 위조가 아닌지 확인한 뒤, 응답의 `claimed_id`에서 SteamID64를 꺼내 저장한다. 비유하면 "학번을 적어 주세요"가 아니라 "학생증을 보여 주세요"다.

- 돌아오는 주소는 서버가 정하고(`return_to`), 그 요청을 시작한 로그인 사용자에게만 붙인다. 시작할 때 무작위 값을 만들어 돌아올 때 맞춰 본다(다른 사이트가 내 계정에 남의 Steam을 붙이는 것을 막는다)
- 다른 계정에 이미 연결된 Steam이면 409. 연결 해제는 `steam_id`만 비우고 기록은 남긴다
- Steam API 키는 필요 없다. OpenID는 M11 Discord OAuth와 흐름이 비슷해 예습이 된다

## 검토한 대안

- **ID 입력 + 프로필 주소 · 사용자 이름 풀기(`ResolveVanityURL`)** — 입력 문제는 풀지만 선점은 그대로다
- **UNIQUE를 빼고 여러 계정이 같은 Steam을 쓰게 함** — 선점은 사라지지만, 남의 공개 라이브러리를 내 계정으로 가져오는 것을 막을 수 없다
- **Steam 프로필 이름에 확인 문구를 넣게 하기** — 사용자가 Steam 설정을 바꿨다 되돌려야 해 번거롭다

## 감수할 것

- Steam OpenID는 OpenID 2.0이라 오래된 방식이고 Steam이 언젠가 바꿀 수 있다. 바뀌면 연결만 안 되고 이미 연결된 계정의 동기화는 계속 된다
- 개발에서 돌아오는 주소가 `localhost`라 Steam이 그대로 받아 주는지 구현할 때 확인한다
