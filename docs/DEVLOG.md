## 2026-11-03 (2) · 상단 메뉴 시안 비교 · 채택 (데스크톱 B)

- A · B · C → 사용자가 B를 골라 B 기반 D ~ G 추가 → **E + G의 아이콘 = H 채택**. F는 나중에 다시 볼 후보로 남김 ([0010](decisions/0010-top-nav.md))

- **확인 못 한 것**: 스크롤할 때 메뉴 동작(정지 그림), 실제 Steam 커버 위 모습, 구현 후 화면

### [설계]
- **선택된 필터 칩을 무채색으로** — 활성 메뉴를 빨강으로 채우면 칩 · 등록 버튼까지 세 군데가 된다. `DESIGN` 4.4절 원칙도 함께 고침
- **새 시안은 파일을 늘리지 않고 `?variant=`로** — 목업끼리 바뀌는 곳이 메뉴뿐이다

### 막힌 것

- **보호 대상을 표시하지 않고 공개 화면을 표시한다** (`meta.public`) — 반대로 하면 새 화면을 만들 때 표시를 빠뜨리는 순간 비로그인으로 들어올 수 있다. 빠뜨렸을 때 막히는 쪽이 안전하다
- **로그인 후 이동은 `push`가 아니라 `replace`** — 뒤로가기로 로그인 화면에 다시 오지 않게 한다
- **복원 중 연결이 끊기면 비로그인으로 시작한다** — 로그인 화면에서 다시 시도하면 "연결에 실패했습니다"가 뜬다. 오프라인 전용 화면은 v1.0 범위가 아니다

  - 교훈: 서버는 항상 `server/`에서 띄운다 (`CLAUDE.md` 자주 쓰는 명령과 같음). 루트 `.env`의 비밀번호가 오류 메시지에 그대로 찍히므로 이 오류 출력은 남에게 보여주지 않는다

**결정 기록**
- **구현 전 설계 검증에서 구멍 2개를 찾아 설계에 넣었다**
  시나리오 10개(정상 재발급, 동시 3건, 재시도도 401, 로그인 401, refresh 401, 연결 끊김, refresh 500, 로그아웃 중 재발급, 늦게 도착한 401, 쿼리 붙은 경로)를 구현된 것처럼 따라갔다.
  ①**늦게 도착한 401** — 옛 TOKEN으로 보낸 요청의 401이 재발급이 끝난 뒤에 도착하면, 처음 설계대로라면 재발급을 또 보낸다. 재사용 감지에는 걸리지 않지만(COOKIE가 이미 새 것) 쓸데없는 rotation이다. 실어 보낸 TOKEN과 지금 TOKEN이 다르면 재발급 없이 바로 재시도하게 했다.
  ②**재발급 중 로그아웃** — 재발급 응답이 로그아웃 뒤에 도착하면 끝난 세션의 TOKEN이 메모리에 다시 들어간다. 로그인 · 로그아웃마다 오르는 번호표로 그 응답을 버린다. 버릴 때는 "지금 주인의 상태"(TOKEN이 있으면 성공)를 돌려줘서, 그 사이 다른 계정으로 로그인했다면 그 TOKEN으로 재시도한다
- **로그인 화면 이동은 client.ts가 하지 않는다**
  client.ts가 라우터 · 스토어를 import하면 순환이 생긴다(9/29 결정과 같은 이유). 실패 사실만 처리기로 알리고, 스토어는 `user`를 비우고, 이동은 다음 단계의 라우터 가드가 `user`를 보고 한다
- **재발급 중 연결이 끊기면 로그아웃시키지 않는다**
  연결 오류(`status 0`)는 세션이 끝났다는 증거가 아니다. 지하철에서 잠깐 끊겼다고 다시 로그인하게 만들면 안 된다
- **실패 처리기는 여러 번 불릴 수 있게 둔다** — 동시 요청 3건이 모두 실패하면 3번 불린다. 하는 일이 `user = null`이라 몇 번 불려도 결과가 같다

**막혔던 점 / 트러블슈팅**
- 증상: "재발급 중 로그아웃" 테스트가 빨간불 — 마지막 요청에 `Bearer new`가 실려 나감
  - 원인: 코드가 아니라 가짜 SERVER가 틀렸다. 로그아웃 뒤에도 refresh에 계속 새 TOKEN을 내주게 만들어서, 두 번째 요청이 정당하게 재발급을 받은 것. 실제 SERVER는 로그아웃 때 refresh COOKIE를 폐기하므로 401을 준다
  - 해결: 두 번째 refresh부터 401을 주게 고치고, 판정도 "마지막 요청"이 아니라 "어떤 요청에도 `Bearer new`가 실리지 않았는가"로 강화
  - 교훈: 가짜 SERVER는 진짜 SERVER의 규칙(rotation · 폐기)을 지켜야 한다. 안 지키면 테스트가 코드가 아니라 가짜의 동작을 검증한다

- `ubuntu-latest`가 2026-10-19부터 Ubuntu 26으로 전환된다는 경고가 **양쪽 job 모두**에서 떴다. 09-27 기록의 연장이고, 그 시점이 출근일 즈음이라 M5 배포와 겹칠 수 있다
- `npm run build` step은 앞 step이 전부 통과해야 도달하는데, 빌드만 깨지고 타입 · 테스트는 멀쩡한 상황을 만들기가 번거로워 **실패를 잡는지는 미검증**이다. "돌아가긴 한다"까지만 확인됨
- `src/lib/utils.ts`(shadcn-vue가 생성, `components.json`이 `@/lib`로 참조)가 `ARCHITECTURE` 6장 `web/` 구조에 없다. shadcn 컴포넌트를 처음 쓰는 시점에 한 줄 추가할 것
- 09-28에 적어둔 "API_SPEC 안에서 `토큰` · `TOKEN` 표기가 섞여 있다"가 **코드 주석에도 번졌다**. `client.ts` · `errors.ts`의 주석이 `SERVER` · `TOKEN` · `REQUESTS` 대문자 표기를 쓰고 있다
- ESLint · Prettier가 없어 따옴표 · 들여쓰기 같은 것을 사람이 검수하고 있다. M2가 끝날 때 도입 여부를 판단할 것
