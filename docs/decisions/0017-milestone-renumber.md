# 0017 · 마일스톤 번호를 실제 순서대로 다시 매기고, 확장 기능은 순서 없이 둔다

- **상태**: 채택
- **날짜**: 2026-11-06
- [0014](0014-steam-discord-before-m6.md)를 대체한다 (순서는 그대로, "번호와 버전은 바꾸지 않는다"를 뒤집음)

## 맥락

0014에서 Steam · Discord를 추첨 · 위시리스트보다 먼저 하기로 하면서 번호는 그대로 뒀다. 그러면 M5 다음이 M8이 되고, 버전(v2.0 · v2.1)도 출시 순서와 어긋난다. 사용자가 번호를 실제 순서에 맞추고, 확장 기능은 뒤로 밀어 순서 없이 병렬로 할 수 있게 하자고 했다. Steam 수동 · 자동 동기화를 한 단계로 합치는 것도 함께 따져 봤다.

## 결정

| 새 번호 | 내용 | 옛 번호 | 버전 |
|---|---|---|---|
| M5.5 | 서버 이사 (12월) | 그대로 | v1.1 |
| M6 | Steam 동기화 (수동) | M8 | v1.2 |
| M7 | Steam 자동 동기화 | M9 | v1.2 |
| M8 | Discord 로그인 | M11 | v1.3 |
| M9 · M10 · M11 | 다음 게임 추첨 · 위시리스트 + 구매 전 경고 · 플레이 세션 + 히트맵 (확장, 순서 없음 · 병렬 가능) | M6 · M7 · M10 | 끝나는 순서대로 v1.4, v1.5 … |

- 수동 · 자동 동기화는 합치지 않는다. 수동만으로 완결돼 배포할 수 있고, 자동은 Redis · 워커라는 새 인프라(`REQUIREMENTS` 1.2절 학습 목표)라 이사한 서버 사양을 보고 설계한다. 합치면 한 단계가 너무 커 중간에 닫을 수 없다
- 옛 기록(`archive/` · 지난 DEVLOG 블록 · 지난 결정 기록)은 고치지 않는다. 옛 번호 → 새 번호 대응표는 [archive/README](../archive/README.md)
- 확장 셋을 병렬로 하면 Alembic 마이그레이션 갈래가 갈린다. 합칠 때 병합 마이그레이션을 만든다

## 검토한 대안

- **번호는 두고 순서만 바꾸기(0014)** — 문서를 덜 고치지만 "M5 다음 M8"이 계속 헷갈린다
- **Steam 수동 · 자동을 M6 하나로** — 위 이유로 단계가 커진다. 사용자도 "합쳐도 괜찮을 듯" 정도였고 따로 두는 안을 골랐다
- **확장 기능에 정해진 순서와 버전** — 지금은 무엇을 먼저 할지 정할 근거가 없다. 끝나는 순서대로 버전을 붙이는 편이 거짓이 없다

## 감수할 것

- 지난 기록의 `M8`(Steam) · `M11`(Discord) 같은 번호가 지금 번호와 다르다. 대응표를 봐야 한다
- 0015 · 0016도 같은 날 옛 번호로 썼다. 고치지 않는다
- 확장 기능의 버전 번호가 미리 정해져 있지 않다
